# Product Ideas — Evaluation & Priority

## 1. 数学证明失败审查与探索工具（Illusion 产品化）

**是什么**：输入一个数学猜想 + 已知约束，输出 SAFE/UNSAFE/UNKNOWN + 结构性障碍诊断。

**可行性**：高。代码已经存在（phase2-8），需要的是 API 包装 + 文档。
**市场**：窄但深。数学系研究生、理论物理团队、AI for Math 公司（如 Leancopilot 用户）。
**壁垒**：L3 分类逻辑是核心 IP，不容易复制。
**风险**：用户需要理解 SRS 框架才能使用，学习曲线陡。
**时间**：2-3 周可出 MVP（CLI + Python 包）。

**判断**：第一个产品的最佳候选。已有代码，已有验证结果，已有论文背书。

---

## 2. 成长性 AI 员工 agent

**是什么**：一个 agent 框架，agent 随时间积累经验（不是每次从零开始）。跨会话记忆 + 任务模式学习 + 自动改进。

**可行性**：中。核心技术是"记忆 + 检索 + 反馈循环"。我们已经在用 memory 系统（`.claude/projects/*/memory/`），但它是手动的。产品化需要自动化这个过程。
**市场**：广。所有用 AI 做重复性工作的人都需要"AI 不要每次都忘记"。
**壁垒**：低。很多团队在做类似的事（MemGPT、Letta、各种 RAG 方案）。
**风险**：红海市场，需要差异化。
**时间**：4-6 周出 MVP。

**判断**：重要但不紧急。先作为内部工具（元调度器的记忆层），验证后再外部化。

---

## 3. 元调度器（Meta-Dispatch）

**是什么**：按任务类型路由到最优 AI 模型，支持对抗迭代，按研究线索追踪成本。

**可行性**：高。LiteLLM 做底层，我们只写上层逻辑。
**市场**：中。独立研究者、小型 AI 团队。但 OpenRouter 已经存在。
**壁垒**：低（路由逻辑简单），除非加上"对抗迭代"和"研究线索追踪"作为差异化。
**风险**：可能只是内部工具，不值得单独卖。
**时间**：1 周出 v0.1。

**判断**：先做内部工具。如果用起来真的好，再考虑产品化。

---

## 4. Token 原生指令集

**是什么**：绕过自然语言的歧义层，直接用结构化的"AI 机器码"与模型通信。类似于 function calling 的极端版本——不是"请帮我做X"，而是一套精确的操作码。

**可行性**：低-中。概念有趣但定义模糊。需要先回答：这和 function calling / tool use 有什么本质区别？
**市场**：不确定。如果能证明它比自然语言 prompt 更高效，市场巨大。
**壁垒**：高（如果能做出来的话）。
**风险**：可能是一个研究方向而不是产品。
**时间**：不确定。

**判断**：放入 lab 继续发酵。需要更具体的定义才能评估。

---

## 5. AI 最优记忆库

**是什么**：跨会话、跨模型的持久化知识图谱。不是简单的 RAG——是一个"AI 的长期记忆"，能在不同模型之间共享上下文。

**可行性**：中。技术上是 vector DB + structured memory + retrieval。但"最优"是什么意思？需要定义。
**市场**：广。与"成长性 agent"高度重叠。
**壁垒**：中。关键差异化在于"什么值得记住"的判断逻辑（我们的 memory 系统已经有这个设计）。
**风险**：与 #2 重复，可能应该合并。
**时间**：3-4 周。

**判断**：合并到 #2（成长性 agent 的子模块）。

---

## 6. 具身机器人

**是什么**：物理世界的 AI agent。

**可行性**：极低（对我们当前资源）。需要硬件、传感器、物理环境。
**市场**：巨大但竞争激烈（Tesla Bot、Figure、1X）。
**壁垒**：我们没有硬件能力。
**风险**：资源不匹配。
**时间**：不适用。

**判断**：放弃。除非找到纯软件切入点（如机器人的"大脑"层，但这本质上就是 agent 框架）。

---

## 7. 账单与审计系统

**是什么**：研究线索级别的 AI 成本追踪 + ROI 分析。

**可行性**：高。就是 cost_tracker.py + 可视化。
**市场**：窄。只有重度 AI 用户需要。
**壁垒**：极低。
**风险**：太小，不值得单独做产品。
**时间**：2-3 天。

**判断**：作为元调度器的子功能，不单独产品化。

---

## Priority Stack

```
之后（验证后）：
  3. 成长性 agent + 记忆库（合并，4-6周）

放弃：
  5. 具身机器人（资源不匹配）
  6. 账单系统（太小，合并到元调度器）
```

## 公司最优形态

**Apophenia = 研究自动化基础设施公司**

不卖单一工具，卖"从问题到答案的最短路径"。产品线：
1. Illusion（诊断：这个问题能不能解？卡在哪？）
2. Meta-Dispatch（执行：用最优模型组合解决问题）
3. Growth Agent（积累：解决过的问题变成未来的加速器）

三者形成闭环：Illusion 诊断 → Meta-Dispatch 执行 → Growth Agent 记住 → 下次 Illusion 更快。
