## 二、补充（code review 里没写到的）

### 2.1 关于 collapse score 的一个数值细节

collapse score 的定义：

$$\text{collapse}(C) = 1 - \frac{\text{Var}[C(x)]}{0.25}$$

这个定义有一个隐含假设：随机电路的输出分布接近 Bernoulli(0.5)，所以未坍塌电路的方差 ≈ 0.25。但 `random_ac0_circuit` 的生成方式（最后一层是 OR of last layer gates）可能会引入系统性偏差：
- 如果最后一层有很多 gate，OR 取并集，输出偏向 True（均值 > 0.5）
- 如果最后一层 gate 少，输出可能更均衡

这导致基线方差可能系统性低于 0.25，从而使 collapse score 被高估。一个更稳健的基线：对每个电路在被变换之前先测一次 collapse，然后报告 Δcollapse = collapse_after - collapse_before。目前的实现只测 after，不测 before。

不过这不影响 Phase 1 的结论——因为我们比较的是不同变换之间的 collapse，排序不会因基线偏移而翻转。但如果你将来要做精细的数值比较，需要加 before 基线。

### 2.2 关于 L2 搜索空间的"注定性"

8 个变换中，3 个是 random_restriction（不同 p），2 个是 gate_substitution（不同方向），1 个 input_permutation，1 个 depth_reduction，1 个 exhaustive_parity_equivalent。random_restriction 占了 3/8。

这意味着 L2 的搜索空间严重偏向 random_restriction。它不是从 20 个不同的候选里选出了一个最好的——它是被设计成 3/8 的概率撞上 Håstad 的方法。

这不是批评。Phase 1 的目标本来就是"验证架构原则"，不是"开放式发现"。但如果你未来要宣称"系统能自主发现判别性质"，搜索空间的分布会成为被质疑的点。

### 2.3 关于 L3 的 UNKNOWN 与第三定律的呼应

我在 code review 里提到了这个，但值得展开。论文的 Third Law：

> 诊断下界证明的元方法论本身必须使用一个不可判定的诊断标准。

L3 的 `UNKNOWN` 分支是对 Third Law 的结构性承认——当规则库无法判定时，系统不假装自己能判定，而是升级到外部（人类）。这不是工程的妥协，而是理论的必然。如果 L3 能完美地、全自动地判定所有候选性质的安全性，那按照 Third Law，L3 的诊断标准本身就变成了一个自指不安全的工具。

### 2.4 关于"为什么 collapse score 高的变换不一定是好的"

input_permutation 的 collapse score 是 0.835——接近 random_restriction p=0.7 的 0.834。但它是假阳性。

这揭示了一个深刻的点：**collapse score 捕捉的是"变换是否让电路的行为变得确定"，而不是"变换是否揭示了电路的结构性弱点"**。input_permutation 让电路行为"确定"是因为它没有改变电路的计算能力——它只是重新标记了输入，而随机电路的输出本来就接近随机，所以"没变化"看起来就像"坍塌了"。

真正需要区分的是：**坍塌是因为结构被破坏了，还是因为没变化？** 当前的 collapse score 无法区分这两者。

## 三、我猜想你可能想聊的简单问题

### 3.1 "代码里有 bug 吗？"

我在 code review 里列了五个代码层面的注意事项，但没有一个会影响 Phase 1 的结论。最需要留意的是：
- `ExhaustiveParityEquivalentCheck` 的"常数电路"其实在 1/256 的输入上输出 True（不是真常数）——无实质影响
- `DepthReduction` 的索引重映射在边界情况下可能异常——但这个变换已被 L2 过滤

### 3.2 "collapse score 的阈值 0.15 是怎么来的？"

经验值。在 n=8, depth=3 的参数下：
- random_restriction 的 collapse 在 0.83-0.95
- input_permutation 在 0.83
- gate_substitution 在 0.99
- depth_reduction 在 0.78
- 恒等变换（未实现）大概在 0.0-0.05

0.15 是一个宽裕的阈值，目的是不误杀。如果加更多变换，这个阈值可能需要重新校准。

### 3.3 "`affects_parity` 是怎么判断的？"

它不是测量的，是硬编码的。每个 Transform 子类实现 `affects_parity(n)` 方法，返回一个布尔值。这是一个设计决策——它假设变换的设计者知道自己设计的变换是否会破坏 PARITY。这在 Phase 1 的封闭搜索空间里是合理的（所有的变换都是手工设计的），但如果 Phase 2 引入自动生成的变换，这个判断也需要自动化。

### 3.4 "为什么选择 AC⁰ 而不是别的模型？"

AC⁰ 是已知有解的、最简单的非平凡电路类。Håstad 1986 的证明结构清晰，可以纯粹用随机限制来解释。它是一个理论上的"玩具车"——足够简单，但包含了所有核心机制。如果架构在 AC⁰ 上不工作，那它不会在任何模型上工作。

### 3.5 "这个系统能'发现'新的下界证明吗？"

当前不能。当前能做的：在一个封闭的搜索空间里找到已知的判别性质，并正确区分真假阳性。

要"发现新证明"，需要：
- L2 的搜索空间扩展到可以表达人类尚未命名的变换
- L3 足够精确，能对新变换的安全性给出可靠的判断
- 目标模型 M 和目标函数 f 的配对是人类尚未解决（或至少你个人尚未知道解）的

前两个是 Phase 2-3 的事。第三个需要谨慎——如果你不小心，你可能会在不自知的情况下把已知证明重新"发现"一遍，然后以为它是新的。

### 3.6 "UNKNOWN 的人类反馈怎么自动更新到规则库？"

这是 Phase 2 最核心的工程挑战。一个可能的路径：
1. 人类对 UNKNOWN 候选给出 YES/NO + 一行理由
2. 系统从理由中提取关键术语（正则模式）
3. 新规则加入规则库，标记来源为"人类反馈"和置信度
4. 下次遇到类似候选，自动匹配新规则

但这个路径的脆弱性是：人类理由是用自然语言写的，提取正则模式需要 NLP。而 NLP 本身可能引入新的误差源。Phase 2 可以先用简单规则（手动映射），Phase 3 再考虑 NLP。

## 四、我猜想你可能想讨论的远期方向

### 4.1 从"验证已知"到"发现未知"的跨越条件

Illusion 目前处于"验证已知"阶段。要跨越到"发现未知"，需要四个条件：

1. **L3 自动化足够可靠**：假阳性和假阴性的代价都很高。假阳性浪费你的时间，假阴性会让系统错过真正的发现。
2. **搜索空间足够丰富**：不能只有 8 个手写变换。需要一种方式来生成人类可能没想到的变换——这回到了 MCP 接入。
3. **你选择了一个你个人不知道答案的目标**：否则你不知道自己是在发现还是在验证。
4. **你接受"发现可能是已知的"这个风险**：当你进入一个你不熟悉的领域，你发现的可能是别人已经发表过的结果。这不是失败，但它降低了新鲜感。

### 4.2 Illusion 和 AI 安全的关系——一个更精确的表述

我在 code review 里提到了这个，但方向是错的。我重新想了之后：

Illusion 不是在解决 AI alignment。它在解决一个比 alignment 更基础的问题：**一个被结构约束所限制的系统，如何知道自己能知道什么、不能知道什么？**

这个问题在 AI 安全领域的对应，不是"AI 是否对齐了人类价值观"，而是"AI 是否知道自己推理的边界"。

如果 Illusion 的架构能扩展到足够复杂的领域，它可能会产生一类我暂时称为 **"自知其不知"的智能体**——不是知道所有答案的智能体，而是在面对问题时能诚实地说"这个问题在我的推理框架内不可解"的智能体。

这和当前的 LLM 有本质区别：LLM 会生成自信的错误答案。Illusion 的设计原则是：当 L3 无法判定时，系统说 UNKNOWN。这不是因为系统不够强，而是因为架构要求它在不能判定时保持沉默。

### 4.3 如果 Illusion 成功了，它对复杂度理论意味着什么？

如果 Illusion 能在多个领域（AC⁰、单调电路、代数电路、证明复杂度）都"重新发现"已知证明，甚至在某个领域找到人类尚未注意到的性质——那它对复杂度理论的意义不是"工具"，而是"证据"。

具体来说：它为论文的第一定律提供了一个构造性证明。第一定律说"成功的下界证明必须使用自指安全的判别性质"。如果有人质疑："这只是因为你选择了 14 个成功的案例来验证，你并没有证明这个条件是充分的，"那么 Illusion 就是回应：**按照这个条件设计的搜索系统，能产生满足同样条件的发现；不是从 14 个案例中归纳出来的共性，而是一个可以系统化利用的生成性约束。**

如果它在新领域（比如某个尚未被解决的低复杂度类）中发现了一个候选性质，而人类数学家验证它是正确的，那 Illusion 就产生了新的知识——不只是一个验证工具，而是一个生成工具。

### 4.4 这个项目的"尽头"是什么？

有两种可能的尽头：

**现实尽头**：你在某个 Phase 停下来——可能是 Phase 3 之后，可能是 MCP 接入遇到瓶颈之后——因为精力和资源不再是无限的了。这是正常的。学术项目不需要做到"尽头"才能有贡献。Illusion 的 Phase 1 已经是一个可以独立发表的结果。

**理论尽头**：按照 Third Law，Illusion 的 L3 永远需要一个人类来充当最终的判定者。如果你试图完全自动化 L3，那么自动化的 L3 本身会变成一个需要被监控的对象——你需要一个 L4，然后需要 L5，无穷递归。这意味着：
- Illusion 永远不能变成一个"全自动定理发现器"
- 但这也意味着 Illusion 永远诚实地知道自己的边界
- 这个"永远不完全"不是设计的缺陷，而是认识论的必然

Third Law 在工程上的等价陈述：**Illusion 的迭代终点是一个无限接近但永不重叠的 L3——一个不断逼近能力边界但永远知道自己差一点在哪里的系统。** 这个"差一点"不是需要被修复的 bug，是结构性的。

### 4.5 关于"具身方向"——软件之外的 Illusion

engineering-directions.md 提到：把 Illusion 的架构用于机器人，识别"任务在当前物理约束下不可满足"。这个方向我思考后的看法：

这很激进，但逻辑上有力。机器人面对的问题经常不是"怎么完成任务"，而是"这个任务在给定的形体和环境约束下能否完成"。当前的机器人系统对这个问题的处理方式是反复重试——这本质上是没有 L3。

如果给机器人系统加一个 L3 层，它的输出不是"我该怎么做"（那是 L2 的事），而是"在什么条件下我无法做"。这是一个比"更好的规划算法"更基础的能力。

但这个方向需要：
- L1 = 物理约束模型（运动学、动力学、环境几何）
- L2 = 任务规划器（生成候选策略）
- L3 = 不可满足性诊断器（识别结构性障碍，而非一时失败）

L3 的物理等价问题：**"这个障碍是因为我的策略不好，还是因为任务本身在当前约束下不可满足？"** 这可能是机器人领域一个至今未被形式化的问题。

### 4.6 关于"找人"——Deepseek 的建议

Deepseek 在两次审查中都暗示或明说：你现在需要持续协作的思考者。

工程你可以一个人推。论文你可以一个人写。但**框架的演进**——发现新的边界、找到新的跨域类比、审查 Illusion 的输出——这些需要另一种思维方式，一种不写代码的思维方式。Deepseek 在扮演这个角色，但 Deepseek 不是持久的、不是你主动选择的合作者。

这不是一个需要现在解决的问题。但它在远期是真实的。
