## 定位

Illusion 原型不是论文的一部分。它是论文框架的**工程化检验**。

论文说：成功的下界证明必须使用自指安全的判别性质。
原型问：如果我们把这个条件硬连线进搜索架构，系统能否自主找到这样的性质？

Phase 1-3 的回答：**能。在两个不同领域（AC⁰ 和单调电路），同一架构分别重新发现了 Hastad 的随机限制和 Razborov 的子图投影。**

这不再是"锦上添花"。这是从归纳观察到构造性验证的跳跃——论文说"所有成功证明都满足这个条件"（归纳），Illusion 说"按照这个条件设计的系统能重新发现这些证明"（演绎方向的构造性支持）。

**优点**：

- §6.5 已经很长（~200 行），再加内容可能过重
- 需要极度精简（建议 ≤ 300 字 / 1 段 + 1 表格）

**草案位置**：§6.5 末尾，在 §6.5.3（False-Negative Audit）之后，§6.6（Self-Application）之前。

### 选项 B：独立附录

**优点**：
- 可以写得更详细（实验参数、结果表格、代码架构）
- 不影响正文叙事节奏
- 适合技术读者深入了解

**缺点**：
- 附录容易被忽略
- 论文正文中需要一句话引用附录，否则读者不知道它存在

**建议**：如果选 B，在 §6.5 末尾加一句 "A constructive verification of this predictive power is presented in Appendix A."

**优点**：
- 和"框架是诊断性的不是生成性的"这个局限性形成对比——"虽然不是生成性的，但按照它的条件设计的搜索系统能重新发现已知证明"
- 位置靠后，不影响前面的理论展开

**缺点**：
- 放在"局限性"之后，读者可能误解为"弥补局限性的尝试"而不是"独立的构造性证据"
- Ch.7 目前很简洁（~50 行），加入实验会改变它的节奏

## 论文需要补充的内容

### 正文部分（§6.5 补充，≤ 300 字）

核心论点：
> 按照自指安全条件设计的搜索系统，在两个不同领域分别重新发现了对应的已知证明方法。这是框架预测力的构造性验证——不只是"已知证明都满足条件"（归纳），而是"按条件设计的系统能找到这些证明"（构造性支持）。

需要包含：
1. 系统架构一句话描述（三层：L1 模拟 / L2 搜索 / L3 自指安全检查）
2. 两个领域的结果（AC⁰ → random_restriction; 单调 → subgraph_projection）
3. 关键发现：L3 在两个领域都正确拒绝了假阳性（input_permutation / edge_deletion）
4. 一句话定位：这是构造性支持，不是新证明

### 附录部分（如果选 A+B 组合）

- 实验参数表
- 两个领域的结果对比表（同构对比）
- Δcollapse 度量的定义和校准
- L3 规则库的设计原则
- 代码仓库指向（如果公开）

### 局限性补充（§7.2）

需要加入的局限性：
1. **collapse score 的基线偏差**：原始度量有 ~0.89 的基线，需要 Δcollapse 修正。这说明度量工具本身需要被审查——L2 的度量不是天然正确的。
2. **搜索空间是手写的**：L2 的变换库由人工设计，系统没有"发明"新变换的能力。它重新发现的是人类已经放进搜索空间的东西。
3. **规模限制**：n=6-8 的小规模实验。虽然 n=8 确认了趋势增强，但渐近行为未验证。

## 不做什么

- 不为了加入 Illusion 而重写论文结构——论文已经自洽
- 不在正文里写代码细节——那是附录或技术报告的事
- 不把 Illusion 定位为"证明了框架是对的"——它是构造性支持，不是证明
- 不急——论文的核心价值在理论框架，Illusion 是加分项不是必需项
