# Phase 2 Report: L3 Automation

> Date: 2026-05-02 ~ 2026-05-04
> Status: Complete (all items done)

---

## Goal

Replace manual L3 (human self-referential safety check) with an automated rule-based checker. Validate the rule library's accuracy and discover its boundaries.

---

## Architecture

`phase1/l3_monitor.py` implements a two-tier pattern matching system:

```
Input: transform_name + description (natural language)
  |
  v
Builtin rules (high confidence)
  |-- UNSAFE patterns (known polynomial-time decidable properties)
  |     permut / symmetr / invariant -> permutation invariance, poly-time
  |     monoton -> monotonicity, poly-time
  |     linear -> GF(2) linearity, BLR test
  |     constant -> constant function, AC^0
  |     depth_reduc / gate_substit -> circuit structure, AC^0
  |     exhaustive_parity_equivalent -> exponential but no structural insight
  |     identity / input_negation -> baseline artifacts
  |-- SAFE patterns (known to exceed AC^0)
  |     random_restrict -> Hastad 1986, Switching Lemma
  |     approximat -> Razborov 1985
  |     algebraic_degree -> Razborov-Smolensky 1987
  |
  v
Learned rules (medium confidence, from learned_rules.json)
  |-- Loaded at import time
  |-- Generated by UNKNOWN learning loop
  |
  v
Output: L3Verdict (SAFE / UNSAFE / UNKNOWN)
  + l3_question (structured question for human review)
  + log_entry (formatted for l3_log.md)
```

Three output modes:
1. **SAFE**: rule match with literature support -> keep candidate
2. **UNSAFE**: rule match, poly-time decidable or brute-force -> discard
3. **UNKNOWN**: no rule match -> escalate to human L3

## Completed Work

### 1. Rule library + pressure tests (2026-05-02 ~ 05-03)

Accuracy on all known transforms: **100% (8/8)**

Pressure test results:

| Experiment | exhaustive collapse | random_restriction collapse | L3 verdict |
|---|---|---|---|
| n=8, seed=42 | **1.000** | 0.879-0.969 | UNSAFE (correct) |
| n=12, seed=7 | **1.000** | 0.887-0.957 | UNSAFE (correct) |

Key finding: `exhaustive_parity_equivalent_check` gets collapse=1.000 (highest of all transforms) but L3 correctly rejects it. Core distinction: **exponential enumeration != self-referential safety** -- the property must reveal WHY AC^0 circuits fail, not merely detect that they do.

### 2. Baseline calibration (2026-05-04)

Added `IdentityTransform` (does nothing) and `InputNegation` (complexity-preserving relabeling) as control transforms.

| Transform | Collapse | Interpretation |
|---|---|---|
| identity | 0.889 | **Baseline** -- measurement artifact |
| input_negation | 0.888 | At baseline -- complexity-preserving |
| input_permutation | 0.892 | At baseline -- false positive confirmed |
| random_restriction (p=0.7) | 0.879 | Near baseline -- weakest structural signal |
| random_restriction (p=0.3) | 0.940-0.969 | Above baseline -- genuine structural collapse |
| exhaustive_parity_equivalent | 1.000 | Far above baseline -- but brute-force |

**Key finding**: The collapse score baseline is ~0.889, not 0. The 0.15 threshold filters only near-zero collapse, not "low" collapse. The meaningful signal is collapse *above* the ~0.89 baseline.

**Implication**: `input_permutation`'s 0.892 is not "somewhat high" -- it is exactly at baseline, indistinguishable from identity. This validates the L3 UNSAFE verdict from a completely independent angle.

### 3. UNKNOWN learning loop (2026-05-04)

Implemented the feedback-to-rule pipeline:

```
Human provides: transform_name + SAFE|UNSAFE + one-line reason
  |
  v
Keyword extraction (stop-word filtering)
  |
  v
Pattern generation (transform name parts + top 3 keywords)
  |
  v
Persist to learned_rules.json
  |
  v
Reload into live pattern library (medium confidence)
```

Verification test:
1. `fourier_concentration` -> UNKNOWN (no rule)
2. Human teaches: SAFE, "deciding whether Fourier mass concentrates on low-degree coefficients requires computing exponentially many Fourier coefficients; exceeds AC^0"
3. Re-check `fourier_concentration` -> SAFE (medium confidence, learned)
4. Check `fourier_weight_analysis` -> SAFE (generalized via "fourier" keyword)
5. `threshold_check` -> UNKNOWN -> teach UNSAFE -> re-check -> UNSAFE (correct)

The learning loop works. Builtin rules fire at high confidence; learned rules at medium confidence. The `[learned]` tag in the reason string makes the provenance visible.

CLI:
```bash
python l3_monitor.py --learn <name> SAFE|UNSAFE "<reason>" [reference]
python l3_monitor.py --show-learned
```

## Engineering Automation Note

Theoretical Third Law: L3's self-reflection is an infinite regress -- complete automation is impossible.

Engineering reality: when the rule library covers all known transform types, the system achieves "cognitive-scope completeness" for the user. The user doesn't need to understand the rule library's internal reasoning; they only need to handle UNKNOWN escalations. This is the correct distinction between theoretical impossibility and engineering sufficiency.

The UNKNOWN learning loop is the bridge: each human judgment on an UNKNOWN candidate narrows the gap between "what the system knows" and "what the user needs." The gap never closes to zero (Third Law), but it can be made arbitrarily small for any finite domain.

### 4. Delta-collapse implementation (2026-05-04)

Replaced absolute collapse (threshold 0.15) with delta-collapse: `collapse_after - collapse_before` per circuit. Threshold: 0.03.

Why: absolute collapse has a ~0.889 baseline (random AC^0 circuits with OR output gate bias toward True). Under the old metric, `identity` (0.891) and `input_permutation` (0.892) both passed the 0.15 threshold.

Verification (n=8, depth=3, seed=42):
- `random_restriction p=0.3`: delta=+0.080 -> CANDIDATE (correct)
- `random_restriction p=0.5`: delta=+0.058 -> CANDIDATE (correct)
- `random_restriction p=0.7`: delta=+0.007 -> rejected (new finding: too weak)
- `input_permutation`: delta=-0.002 -> rejected (false positive eliminated at L2)
- `identity`: delta=+0.005 -> rejected
- `exhaustive_parity_equivalent`: delta=+0.115 -> CANDIDATE -> L3 UNSAFE (correct)

Code fixes applied from strict review: `import itertools` moved to top of transforms.py, redundant imports removed from run_experiment.py, identity rule comment updated, duplicate docs removed.
